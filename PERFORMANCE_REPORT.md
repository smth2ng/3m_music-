# Производительность 3М MUSIC

> Это исходный аудит до исправлений. Последующие изменения и повторные проверки описаны в [FIX_IMPLEMENTATION_REPORT.md](FIX_IMPLEMENTATION_REPORT.md).

Измерения выполнены 23 ноября 2026 года на локальной сборке `7d8c0d3` инструментом Lighthouse 13.6.0 и системным Chromium. Эти числа являются лабораторными. Они не являются field Core Web Vitals, INP реальных посетителей или SLA хостинга.

## Методика и ограничения

На каждой из пяти страниц выполнен один запуск mobile и один desktop. Использован стандартный мобильный профиль Lighthouse с simulated throttling и preset desktop для настольного. Точные configSettings и environment сохранены в JSON каждого запуска. Профиль mobile Lighthouse использует собственный viewport, он отличается от отдельной адаптивной матрицы.

Сервер локальный, без CDN, TLS и компрессии хостинга. Кэш-заголовки тестового сервера не описывают GitHub Pages. Запросы Яндекс Карты блокировались явно, поэтому время и байты карты исключены. Базовые Lighthouse-запуски выполнены с пустым браузерным хранилищем. Заполненное демо с 12 релизами проверено отдельным CDP-профилем.

Значения могут различаться при повторном запуске. INP в Lighthouse navigation не измерялся. TBT не заменяет INP.

## Медленная сеть и слабое устройство

Дополнительная проверка выполнялась CDP с CPU slowdown ×4, задержкой 150 мс, download 200000 байт/с и upload 93750 байт/с. Это отдельный прямой throttling-профиль, его нельзя сравнивать по абсолютным числам с simulated Lighthouse как одинаковый эксперимент.

| Сценарий | LCP, мс | Накопленный CLS наблюдателя | Байты ресурсов без HTML | Число ResourceTiming-записей | EventTiming |
| --- | --- | --- | --- | --- | --- |
| desktop | 272 | 0.005132 | 532570 | 12 | 0 записей |
| slow-mobile | 2772 | 0 | 532570 | 12 | 3 записей |
| slow-mobile-12-releases | 2788 | 0 | 532254 | 11 | 0 записей |

CDP-проба измеряла initial viewport до полного скролла, затем открывала и закрывала модальное окно. Сумма CLS в наблюдателе не использует полную агрегацию session window стандарта Web Vitals. ResourceTiming исключает главный HTML и может не включать ещё не запрошенные lazy-изображения. Обложки 12 деморелизов являются data URI и не создают отдельных HTTP-запросов, но увеличивают localStorage и декодирование. Эти показатели нельзя трактовать как размер всей заполненной страницы на реальном CDN.

EventTiming относится только к синтетическому открытию диалога и Escape. Полевой INP отсутствует. Отсутствие событий длиннее порога наблюдателя не означает INP=0.

## Неиспользуемые ресурсы и блокировки

- Lighthouse image-delivery-insight для главной mobile оценивает возможную экономию примерно 457 KiB. Это оценка инструмента по размерам, не гарантированная экономия при сохранении визуального качества.
- CSS 19075 символов загружается общим файлом. В CDP desktop после скролла и работы диалога использовано 9803 символа. Непокрыто около 48,6% CSS в этом конкретном состоянии. В других страницах и media queries правила могут быть нужны.
- Упоминания footer-logo.svg, .studio-intro и .section-links не найдены вне самого ресурса и CSS. Это отдельные подтверждения статического анализа.
- Lighthouse сообщает о неминифицированном CSS с оценкой экономии около 3 KiB.
- CSS подключён обычным link rel=stylesheet и блокирует первый render. Скрипты defer и module не являются обычными синхронными блокирующими script.
- Цепочка module imports добавляет несколько сетевых шагов в админке и релизах. В текущем объёме это небольшой вклад, измеренного большого TBT нет.
- JS coverage сохраняется в сыром V8-формате для версий Playwright с functions. Процент неиспользуемого JS по этому формату не выдумывается.
- В серверном коде и клиенте сохранён неактивный backend-путь, но его нельзя удалять только по покрытию деморежима.

## Изображения и стабильность

Статические исходные фотографии имеют width/height. Динамически созданные img преподавателей и профиля не резервируют размеры HTML-атрибутами. Lighthouse отмечает unsized-images на преподавателях. Большой CLS в проверенном базовом сценарии не воспроизведён. Рекомендуется зарезервировать aspect-ratio или размеры до загрузки и повторить проверку с непопавшим в кэш фото.

## Кэширование

Сборка добавляет content hash в URL JS/CSS, в том числе module imports. Это проверено локальными сетевыми URL. Lighthouse cache-insight оценивает тестовый сервер без Cache-Control и поэтому не доказывает плохое кэширование GitHub Pages. Проверить production response headers не удалось.

## Приоритетный план

1. Подготовить responsive images с srcset/sizes для исходных групп и карточек.
2. Зафиксировать aspect-ratio динамических фотографий.
3. После наполнения повторить Lighthouse для реальной карточки артиста и 12 настоящих обложек.
4. Очистить подтверждённо неиспользуемые ресурсы и старые CSS-правила после проверки всех страниц.
5. Рассмотреть минификацию CSS и JS при сборке, сохранив диагностику.
6. Проверить настоящее сжатие и кэширование на GitHub Pages при доступе.
7. Повторить лабораторный профиль на той же машине и собрать полевые данные после запуска.
