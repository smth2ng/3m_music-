# Полный аудит 3М MUSIC

> Это исходный аудит до исправлений. Последующие изменения и повторные проверки описаны в [FIX_IMPLEMENTATION_REPORT.md](FIX_IMPLEMENTATION_REPORT.md).

Аудит выполнен 23 ноября 2026 года. Часовой пояс отчёта Europe/Moscow. Зафиксирован коммит `7d8c0d3bd5ff93c9ac622ab1623eccd6ec823d65`.

Проверялась локальная production-сборка с размещением в подпапке `/3m_music-/`. Опубликованный адрес недоступен из среды из-за HTTP CONNECT 403. Нельзя подтвердить совпадение текущего деплоя с этим коммитом, работоспособность внешней карты и реальное поведение CDN.

Исходные файлы, package.json и основной lockfile сохранены без изменений. Созданы только отчёты и отдельный каталог audit. Коммитов, push, публикации, реальных заявок и правок данных чужого браузера не выполнялось. Контрольные суммы исходных файлов проверены. [audit/results/source-integrity.txt](audit/results/source-integrity.txt)

## Проверенное покрытие

- 8 HTML-маршрутов, 15 заданных размеров и их альбомные варианты — 240 базовых записей.
- Ещё 12 уникальных комбинаций заполненных страниц на четырёх ключевых ширинах. Они повторялись в функциональных прогонах, в сыром JSON всего 276 записей.
- 33 уникальных запусков axe по странице и ширине, включая редактор админки.
- 13 функциональных проверок в итоговом прогоне — 8 прошли, 5 завершились подтверждёнными расхождениями. Остальные точечные проверки имеют отдельные артефакты.
- 10 реальных запусков Lighthouse и 3 дополнительных CDP-профиля производительности.
- 59 PNG-скриншотов в audit/screenshots. Фикстуры с тестовыми фотографиями явно названы populated. Они не являются содержимым продакшена.

Матрица проверяла геометрию, overflow, загрузку изображений, заголовки, ссылки, консоль и сетевые сбои. Она не означает ручной просмотр каждого пикселя всех 240 состояний. Вручную просмотрены ключевые скриншоты и подтверждения найденных дефектов.

Firefox и WebKit отсутствуют. Установка обоих предпринята, загрузки запрещены сетью. Эмуляция 200% выполнена уменьшением CSS-viewport вдвое, дополнительно проверен text-zoom через корневой font-size. Настоящий desktop browser zoom и скринридеры не подтверждены.

## Структура проекта и зависимости

- public содержит статические страницы, один CSS, обычные JS-файлы и ES-модули. Продуктовых React/Vue или сторонней UI-библиотеки нет.
- server.mjs раздаёт public или dist. scripts/admin-server.mjs реализует отдельный серверный вход и GitHub proxy. Этот сервер не исполняется на GitHub Pages.
- scripts/build.mjs копирует public в dist, генерирует страницы артистов и добавляет хэши JS/CSS, включая статические module imports.
- scripts/artists.mjs строит статические профили из public/data/artists.json.
- В production нет npm runtime-зависимостей. Единственная devDependency проекта — Playwright 1.62.1.
- npm audit сообщил 0 известных уязвимостей. npm outdated сообщил latest Playwright 1.65.1. Сам факт наличия новой версии не означает уязвимость.
- Шрифт Arial с системными fallback Helvetica/sans-serif, сетевых шрифтов нет. Фотографии локальные WebP, логотипы SVG.
- Навигация и относительные пути проверены под /3m_music-/. Ссылки на внешние платформы проверялись по форме URL и защитным атрибутам, фактическое прослушивание не выполнялось.

## Сильные стороны, подтверждённые проверкой

1. Основное меню работает на мобильном и настольном viewport.
2. Обычная матрица 320–2560 px и её альбомные варианты не выявила глобальный горизонтальный overflow.
3. Модальное окно открывается, закрывается кнопкой, Escape и кликом по фону. Tab не уходит на фоновые контролы, фокус возвращается на кнопку заявки.
4. Свайп, горизонтальное колесо и переключение с фокусом на контейнере карусели работают. Отдельный дефект фокуса карточки описан ниже.
5. В локальном демо проходят CRUD артистов, преподавателей и релизов, валидация HTTPS и подтверждение удаления.
6. У ссылок target=_blank есть rel с защитой. В проверенном текстовом вводе HTML выводится текстом, innerHTML в коде сайта не используется.
7. Reduced motion отключает scroll snap и анимационное улучшение. Видимый focus-outline на базовых клавиатурных ссылках есть.
8. Мобильный и настольный Lighthouse не зафиксировал TBT или CLS в базовом сценарии. Это не исключает сдвигов в других состояниях.

## Подтверждённые проблемы

Серьёзность относится к проверенному сценарию. Critical-дефектов не подтверждено. Известные временные ограничения вынесены отдельно. Оценки сложности ориентировочные, без согласования архитектуры они не являются сроками поставки.

## Доступность и WCAG 2.2 AA

Автоматические проверки охватили доступные axe-теги WCAG 2 A/AA, WCAG 2.1 A/AA, WCAG 2.2 AA и отдельно best practices. Это не полная проверка соответствия стандарту.

- Подтверждён label-content-name-mismatch у карты, относящийся к WCAG 2.5.3.
- Зафиксирована потеря клавиатурного фокуса в карусели. Нужна корректировка поведения и повторная проверка клавиатурной последовательности.
- Встречаются отсутствие H1, неверная skip-link и пропуск уровней заголовков. Часть соответствующих axe-правил относится к best practices.
- Axe на reduced-motion матрице не нашёл постоянного нарушения контраста. Lighthouse с обычными анимациями пометил внеэкранные секции с opacity .12, например контраст заголовка релизов 1,26 и текста 1,17. При прокрутке секция становится opacity 1. Это различие состояния измерений, постоянное нарушение читаемости после завершения анимации не подтверждено.
- Размеров контролов меньше 24×24 CSS px автоматический геометрический проход не обнаружил. Это не заменяет проверку исключений и расстояний WCAG 2.5.8.
- Скринридеры, системный high contrast, iOS VoiceOver и Android TalkBack не запускались. Полное соответствие WCAG не заявляется.

## SEO и индексация

Все основные готовые страницы имеют title и lang=ru. Метаописания повторяются, служебная админка не имеет noindex. Исходные пустые страницы артистов имеют title, но лишены основного содержимого. Generic artist.html наполняется JavaScript, при неизвестном ID отдаётся HTTP 200 с текстом ошибки. Публичный серверный 404-шаблон GitHub Pages и текущие заголовки индексации проверить нельзя.

Robots.txt и sitemap.xml локально возвращают 404. Это не означает запрет индексации всего сайта. Canonical, OG и JSON-LD отсутствуют. Lighthouse SEO 100 на основных страницах не подтверждает индексацию, качество описаний и наличие расширенных сниппетов.

## Безопасность и устойчивость

- XSS-проба в описании артиста отобразилась как текст, инъекции img не произошло.
- Схема javascript: отклоняется формой ссылок и статической сборкой.
- Код генерации HTML экранирует текст. Сетевые токены или значения серверных переменных в артефакты не выводились.
- Серверная локальная проверка с вымышленными настройками подтвердила 401 без сессии, 403 для чужого Origin, 401 для неверного пароля, HttpOnly/SameSite cookie, 404 для неразрешённого proxy-маршрута и инвалидирование сессии после logout.
- В тесте HTTP cookie закономерно без Secure. В исходнике Secure включается для ADMIN_ORIGIN с https. Реальное HTTPS-развёртывание не тестировалось.
- Обработка плохого JSON возвращает 502, см. QA-17. Тест не обращался к GitHub с записью.
- С отключённым JavaScript доступны основная информация, меню, телефон и начальные статические карточки. Демоартисты, деморелизы и админские действия не работают. Это ограничение архитектуры клиентских данных.
- Отсутствует автоматическая публикация новых фотографий для других пользователей в деморежиме. Браузерная квота также ограничивает общий объём base64-фото. Не проверялась реальная сохранность данных после пользовательской очистки браузера.

Клавиатурная модель карусели, резерв места под админские действия, ошибки локального хранилища, skip-link страницы артиста, поисковые метаданные. Единую цветовую палитру и стиль карточек сохранять.

## Функции для согласования

Общая публикация данных, ревизии для конфликтов, экспорт/восстановление демоданных, полноценные страницы артистов, подтверждённые примеры работ и при необходимости способ связи помимо звонка. Эти функции не добавлялись во время аудита.

## Ускорение загрузки

В первую очередь responsive images. Затем оценить разбиение или очистку CSS по состояниям, минификацию сборки и корректное кэширование после проверки реальных заголовков GitHub Pages. Хэши JS/CSS уже есть, удалять их не требуется.

## Пошаговый план улучшений

1. Получить разрешение на конкретные исправления по ID.
2. Исправить фокус, hidden-превью, skip-link и доступное имя карты.
3. Добавить проверку схемы хранилища и защиту от перезаписи из второй вкладки.
4. Отдельно выбрать постоянное хранение и публикацию с учётом текущего GitHub Pages.
5. Наполнить реальные страницы артистов, преподавателей и релизов.
6. Подготовить responsive images, повторить мобильный Lighthouse на том же профиле.
7. Настроить метаданные, sitemap и noindex админки.
8. Повторить матрицу, axe, CRUD и ручные проверки по найденным ID.
9. На доступном продакшене подтвердить деплой, карту, сетевые заголовки и внешние ссылки.
10. Перед публикацией проверить Firefox, WebKit и реальные мобильные устройства.

Полные результаты находятся в TEST_RESULTS.md, RESPONSIVE_REPORT.md, PERFORMANCE_REPORT.md и UX_UI_RECOMMENDATIONS.md. Ни один из пунктов плана не был внесён в исходный код.
