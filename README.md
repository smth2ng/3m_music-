# 3М music

Адаптивный сайт продюсерского центра 3М music. HTML, CSS и JavaScript без клиентских библиотек; фотографии и векторные логотипы извлечены из макетов и хранятся локально.

## Запуск

Нужен Node.js 20 или новее.

```sh
npm ci
npm run dev
```

Сервер слушает порт 3000; другой порт задаётся переменной `PORT`. Рабочий каталог — корень репозитория.

```sh
npm run build
SERVE_DIST=1 npm start
```

Сборка создаёт `dist/`, который можно разместить на любом хостинге статических сайтов.

## Поведение

- Карточки артистов переключаются горизонтальной прокруткой над карточкой, клавишами ←/→ или горизонтальным свайпом. Вертикальная прокрутка листает страницу и не переключает артистов. Нажатие открывает отдельную страницу артиста в новой вкладке; страницы `public/artists/artist-1.html` и `artist-2.html` содержат фотографию и явное сообщение о подготовке информации. Фоновая карточка затемняется оверлеем 38%; переходы учитывают `prefers-reduced-motion`.
- Из верхнего меню можно перейти на главную и прямо к артистам, преподавателям, контактам. Артисты, преподаватели и контакты открываются на отдельных страницах. Услуги и этапы работы размещены на главной.
- «Оставить заявку» открывает контактное окно с телефоном Михаила. Серверная отправка заявки не подключена: в исходных материалах нет формы или адреса обработчика.
- Ссылка в контактах открывает адрес центра в Яндекс Картах.
- Текст остаётся доступным для поиска и выделения; сайт не использует изображение макета вместо HTML. В SVG текст переведён в кривые; для текстовой верстки используется Arial с системными заменами.

## Проверки

```sh
npm test
```

Тесты Playwright запускают свой сервер на порту 4173 и проверяют загрузку изображений и отсутствие горизонтальной прокрутки на 7 ширинах от 320 до 1920 px. На 390 и 1440 px дополнительно проверяются расположение основных блоков, меню, навигация, карусель, контактное окно и анимация прокрутки. На 390 px также проверяется сенсорный свайп.

Если Chromium не установлен в системе, выполните `npx playwright install chromium`. Можно задать `CHROMIUM_PATH` для своего исполняемого файла браузера.

## GitHub Pages

Workflow `.github/workflows/pages.yml` собирает и публикует `dist/` при каждом push в `main`. В настройках репозитория Pages → Source должно быть выбрано GitHub Actions.

Публичный адрес: https://smth2ng.github.io/3m_music-/

Относительные пути к ресурсам позволяют запускать сайт как в корне домена, так и в каталоге репозитория на GitHub Pages.

## Анимация прокрутки

Секции главной страницы появляются с плавным смещением и масштабом, текст сохраняет читаемость; карточки внутри — с небольшой последовательной задержкой. Полупрозрачные панели используют backdrop blur и светлую стеклянную кромку. Между секциями увеличены отступы.

CSS scroll snap в режиме proximity мягко притягивает вид к ближайшей секции, сохраняя возможность читать длинные блоки. Горизонтальная карусель артистов работает независимо. При включённом системном уменьшении движения анимации и притяжение отключены; без JavaScript содержимое остаётся видимым.

## Управление артистами

Админка находится по адресу `/admin/` на Node.js-сервере. Для серверной публикации задайте через секреты хостинга:

- `ADMIN_PASSWORD` — длинный уникальный пароль администратора.
- `ADMIN_GITHUB_TOKEN` — fine-grained GitHub token с доступом только к `smth2ng/3m_music-` и разрешением Contents — Read and write.
- `ADMIN_ORIGIN` — точный публичный origin сервера с HTTPS без завершающего слеша, например `https://admin.example.com`.

Команды хостинга — установка `npm ci`, сборка `npm run build`, запуск `SERVE_DIST=1 npm start`. Используйте Node.js 20+ и одну реплику сервера. Сессии живут в памяти до 8 часов, после перезапуска требуется повторный вход. Хостинг должен передавать браузерный заголовок Origin без изменений.

Для локального запуска используйте `ADMIN_ORIGIN=http://localhost:3000` и задайте остальные секреты через окружение. Пароль и токен не записывайте в репозиторий. В браузер отправляется только защищённая HttpOnly cookie с идентификатором сессии. Запись в GitHub выполняет сервер. Рабочий токен с правом записи всё равно требуется.

GitHub Pages продолжает публиковать публичный сайт. Админку нужно открывать на отдельном Node.js-хостинге: GitHub Pages не выполняет серверную проверку пароля.

Добавьте название, главное фото и при необходимости описание, логотип, дополнительные фотографии, HTTPS-ссылку на видео и платформы прослушивания. Поддерживаются PNG, JPEG и WebP до 8 МБ на файл. Ссылки на платформы вводятся по одной в строке в формате `Название | https://адрес`. При редактировании снимите флажок у фотографии, чтобы убрать её из галереи. Удаление артиста требует подтверждения.

Сохранение создаёт один коммит в main с данными и фотографиями. Публичный сайт обновляется после успешного workflow GitHub Pages. При конфликте параллельных изменений нажмите «Обновить данные» и повторите правку на актуальной версии. Файлы старых фотографий остаются в репозитории, но удалённые артисты и фотографии исчезают со страниц после сборки.

Данные находятся в `public/data/artists.json`. Команда `npm run build` создаёт страницы артистов, добавляет их в карусель главной и сетку артистов, а также формирует HTML преподавателей и релизов. Для локальной проверки используйте `npm run build`, затем `SERVE_DIST=1 npm start`. Две исходные карточки сохраняются.

### Преподаватели в деморежиме

После входа в админку раздел «Преподаватели» позволяет добавлять, удалять с подтверждением и редактировать преподавателей, включая существующие карточки Михаила Гришина и Полины Гевель: имя, описание, замену или удаление фото. Изменения сохраняются отдельно от артистов в текущем браузере и сразу подхватываются страницей преподавателей, включая открытую в другой вкладке. На настроенном Node.js-хостинге сохранение этого раздела создаёт коммит с общей коллекцией преподавателей.

### Недавние релизы

Блок «Недавние релизы» находится на главной сразу после «О центре». В одноимённом разделе админки можно добавлять, редактировать и удалять релизы. Для релиза нужны название, артист из выпадающего списка, обложка PNG/JPEG/WebP до 8 МБ и HTTPS-ссылка для кнопки «Слушать». Новые релизы располагаются первыми. Список артистов загружается при открытии формы, включая изменения, сделанные в демоадминке. Если артист удалён, у его релиза сохраняется последнее указанное имя.

В текущем деморежиме релизы сохраняются в localStorage текущего браузера и подхватываются главной в соседних вкладках. На настроенном Node.js-хостинге релизы публикуются через GitHub вместе с обложками.


### Режимы сохранения и резервные копии

На GitHub Pages включён временный деморежим с паролем 6767. На Node.js-хостинге при наличии всех трёх ADMIN_* переменных сервер автоматически отдаёт конфигурацию для настоящего входа по паролю. В этом режиме артисты, преподаватели и релизы сохраняются в GitHub, изображения загружаются в assets/uploads, а workflow публикует общие данные после сборки. До завершения деплоя новые файлы изображений могут ещё отсутствовать на публичном сайте.

В деморежиме защита от двух вкладок использует сравнение версии коллекции и Web Locks, если API доступен. Устаревшая форма отклоняется с сообщением. Исходные данные остаются сохранены. В серверном режиме сравнивается версия файла коллекции, а ссылка ветки обновляется без force. Изменение другого раздела не создаёт ложного конфликта файла.

Кнопка «Скачать резервную копию» сохраняет данные трёх разделов. Восстановление выполняется по одному выбранному разделу с подтверждением. Повреждённые данные можно сохранить в копию до восстановления. Текстовые данные выводятся безопасно, невалидные записи изолируются.

Сборка создаёт canonical, Open Graph, sitemap.xml и структурированные данные с известными названием, адресом и телефоном центра. Служебная админка, generic-просмотр и две временные страницы артистов помечены noindex. Изображения исходных групп имеют адаптивные варианты 256/480/800 px.
