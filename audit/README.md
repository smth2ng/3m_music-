# Независимый аудит 3М MUSIC

Набор создан 23 ноября 2026 года для коммита 7d8c0d3. Рабочий код не меняет. Данные CRUD записываются только в свежие тестовые браузерные контексты.

## Запуск

Текущие npm-команды используют retest.cjs, fix-regressions.cjs и performance-retest.cjs. Их результаты находятся в retest-results/, скриншоты в retest-screenshots/. Исходный аудит до исправлений сохранён в results/ и screenshots/. Для его повторения на исходном коде нужен коммит 7d8c0d3.

Из корня проекта выполните

```sh
npm run build
npm ci --prefix audit
npm test --prefix audit
npm run performance --prefix audit
```

Нужен установленный Chromium. По умолчанию используется /usr/bin/chromium. Для основного и performance runner можно задать CHROMIUM_PATH. Если Chromium отсутствует, установите браузеры через Playwright из каталога audit и укажите подходящий путь. Firefox и WebKit проверяются на доступность, в исходной среде их установка заблокирована сетью.

Основной runner использует порт 4380 и отдаёт dist под /3m_music-/. Performance runner использует 4381. Дополнительные сценарии используют 4382–4385. Запускайте каждый дополнительный сценарий после завершения предыдущего. Карта блокируется в воспроизводимых тестах. Это явно отмечается в результатах и не является доказательством ошибки внешнего сервиса.

## Дополнительные сценарии

- targeted.cjs проверяет скрытые превью, фокус, XSS-текст и 12 релизов.
- visual-probes.cjs сохраняет маленький viewport, аппроксимацию масштаба и админскую геометрию.
- concurrency.cjs подтверждает потерю преподавателя при сохранении двух вкладок.
- build-fixture.cjs проверяет генерацию в временной копии проекта, экранирование и отклонение javascript URL.
- security.cjs проверяет локальный Node API с вымышленными настройками. Внешних GitHub-запросов с записью не делает.

Основной runner возвращает ненулевой exit code при провале assertion. Пять провалов в зафиксированном результате соответствуют дефектам, описанным в отчёте. Их нельзя исправлять отключением тестов.

AUDIT_CHECKS_ONLY=1 повторяет функциональные сценарии с ранее сохранённой матрицей. AUDIT_PERF_CUSTOM_ONLY=1 повторяет только CDP-профили при существующем performance-summary.json. Флаги полезны для восстановления инструментального прогона, полный независимый прогон выполняется без них.

## Артефакты

В results находятся исходные JSON, журналы, Lighthouse и контрольные суммы. В screenshots находятся локальные изображения и INDEX.md. Файлы с populated используют тестовый профиль и повторно используют существующее фото проекта как визуальную фикстуру. Они не являются реальными карточками артистов или релизами.

Точные ограничения покрытия и найденные проблемы указаны в корневых FULL_AUDIT_REPORT.md, RESPONSIVE_REPORT.md, PERFORMANCE_REPORT.md, UX_UI_RECOMMENDATIONS.md и TEST_RESULTS.md.

В текущей среде зависимости установлены вне проекта в /tmp/3m-audit-tools. Для повторения такого размещения задайте AUDIT_TOOLS путём к каталогу с зависимостями. Основные package.json и package-lock.json проекта не менялись.
